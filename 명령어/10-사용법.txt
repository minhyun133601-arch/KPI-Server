KPI 서버 명령어 사용법

[먼저 알아둘 것]
- 이 폴더의 명령은 서버 PC에서 실행합니다.
- 현재 서버는 0.0.0.0:3100 으로 열려 있습니다.
- 내부망 접속 주소: http://192.168.1.237:3100/login
- 외부 사무실 접속 주소: http://59.21.146.202:3100/login
- 내부 주소와 외부 주소는 브라우저 기준으로 서로 다른 접속 주소입니다.
  - 예: 내부 주소로 로그인한 뒤 외부 주소로 접속하면 다시 로그인할 수 있습니다.

[로그인 / 쿠키 / 세션]
- 한 번 로그인하면 브라우저에 kpi_session 쿠키가 저장됩니다.
- 같은 컴퓨터라도 아래 조건이 같아야 재로그인 없이 유지됩니다.
  - 같은 브라우저
  - 같은 브라우저 프로필
  - 같은 접속 주소(host)
- 현재 세션 기본 유지시간은 12시간입니다.
- 아래 경우에는 다시 로그인해야 합니다.
  - 12시간 경과
  - 로그아웃 실행
  - 브라우저 쿠키 삭제
  - 시크릿 모드 사용
  - 다른 브라우저 사용
  - 내부 주소와 외부 주소를 바꿔서 접속

[데이터 유지]
- 서버를 열고 닫는다고 데이터가 자동으로 지워지지 않습니다.
- 아래를 직접 지우지 않는 한 기존 데이터는 유지됩니다.
  - internal-server\var\central-runtime\postgres\data
  - internal-server\var\prod
- 사용자 계정도 직접 재설정/삭제하지 않는 한 유지됩니다.

[계정 규칙]
- 새로 만드는 로그인 아이디(username)는 한글 입력이 불가합니다.
- username 은 영문/숫자와 . _ - 만 사용할 수 있습니다.
- 한글 이름은 display name 에 넣어 주세요.
- 기존에 이미 만들어진 한글 username 계정은 별도로 존재할 수 있습니다.
- 예시
  - 가능: kpiadmin, minhyun01, staff-01, staff_01
  - 불가: 김민현, 홍길동, 민현01

[명령어 목록]
1. 01-부팅시-자동실행-등록.cmd
   - 윈도우 부팅 시 KPI 서버가 자동 실행되도록 예약 작업을 등록합니다.
   - SYSTEM 계정으로 실행되며, 부팅 후 약간의 지연 뒤 서버를 올립니다.
   - PC를 항상 켜 두는 중앙 서버로 운영할 때 사용합니다.

2. 02-부팅시-자동실행-해제.cmd
   - 01번에서 등록한 윈도우 부팅 자동 실행 예약 작업을 제거합니다.
   - 더 이상 부팅 시 자동으로 서버를 올리지 않게 할 때 사용합니다.

3. 03-서버-열기.cmd
   - KPI 서버를 실행합니다.
   - 내부적으로 아래 작업을 포함할 수 있습니다.
     - 로컬 PostgreSQL 시작
     - 환경 파일(.env.production.local) 준비
     - 저장 폴더(var/prod) 준비
     - 자동 마이그레이션 수행
   - 처음 실행일 때만 DB 초기 세팅이 들어가고, 그 이후에는 기존 DB를 재사용합니다.
   - 기존 데이터는 유지됩니다.

4. 04-서버-닫기.cmd
   - KPI 서버를 종료합니다.
   - 로컬 PostgreSQL도 함께 종료합니다.
   - 종료만 하는 것이며, 데이터 삭제는 아닙니다.

5. 05-서버-상태-확인.cmd
   - 서버 PC 자체에서 현재 서버 상태를 확인합니다.
   - 127.0.0.1 기준으로 /api/health 를 확인합니다.
   - 출력 의미
     - SERVER UP: 서버 정상
     - SERVER DOWN: 서버 미실행 또는 접속 실패

6. 06-오너-생성.cmd
   - 최초 오너(owner) 계정을 생성합니다.
   - 이미 오너가 있으면 실행되지 않습니다.
   - 새 로그인 아이디(username)는 영문/숫자와 . _ - 만 허용합니다.
   - 한글 이름은 Owner display name 에 넣어 주세요.
   - 입력 항목
     - Owner username
     - Owner display name
     - Owner password
     - Confirm owner password
   - 주의
     - 오너는 최고 관리자 계정입니다.
     - 최초 1회만 만드는 용도입니다.

7. 07-일반직원-생성.cmd
   - 일반 직원 계정을 생성합니다.
   - 오너 계정으로 인증한 뒤 생성합니다.
   - 생성 역할은 viewer 입니다.
   - 새 직원 로그인 아이디(username)는 영문/숫자와 . _ - 만 허용합니다.
   - 한글 이름은 Employee display name 에 넣어 주세요.
   - 입력 항목
     - Owner username
     - Owner password
     - Employee username
     - Employee display name
     - Employee password
     - Confirm employee password
   - 참고
     - Owner username 은 기존 오너 계정 로그인용입니다.
     - Employee username 은 새로 만들어질 직원 계정 아이디입니다.

8. 08-비밀번호-재설정.cmd
   - 대상 사용자 비밀번호를 새로 설정합니다.
   - 오너, 관리자, 일반 직원 모두 가능합니다.
   - 입력 항목
     - Reset target username
     - New password
     - Confirm new password
   - 참고
     - 비밀번호는 찾는 방식이 아니라 재설정 방식입니다.
     - 원래 비밀번호를 읽어오는 기능은 없습니다.

9. 09-사용자-삭제.cmd
   - 대상 사용자 계정을 삭제합니다.
   - owner 계정은 삭제되지 않게 막혀 있습니다.
   - 실제 삭제이므로 주의해서 사용합니다.
   - 입력 항목
     - Delete target username
     - DELETE 확인 문구
   - 참고
     - 비활성화가 아니라 실제 삭제입니다.
     - 퇴사자 계정 정리나 잘못 만든 계정 삭제에 사용합니다.

10. 11-DB-콘솔-열기.cmd
   - PostgreSQL DB 콘솔(psql)을 바로 엽니다.
   - 현재 운영 env 파일(.env.production.local)의 KPI_DATABASE_URL 로 접속합니다.
   - 서버가 꺼져 있어도 로컬 PostgreSQL 클러스터가 있으면 먼저 시작을 시도합니다.
   - "콘솔"은 버튼을 누르는 화면이 아니라, 검은 창에 글자를 직접 입력하는 방식입니다.
   - 이 명령을 실행하면 보통 `kpi_internal=>` 같은 글자가 보입니다.
     - 이 표시가 나오면 정상 연결된 상태입니다.
     - 여기서는 마우스로 선택할 것은 없습니다.
     - 보고 싶은 내용을 글자로 입력한 뒤 Enter 를 누르면 됩니다.
   - 가장 자주 쓰는 입력 예시
     - \dt
       - 현재 DB 안의 테이블 목록 보기
     - select * from app_users;
       - 사용자 테이블 내용 보기
     - select * from app_documents limit 20;
       - 문서 테이블에서 앞 20개만 보기
     - \q
       - DB 콘솔 종료
   - 주의
     - SQL 문장은 끝에 세미콜론(;)을 붙이는 것이 안전합니다.
     - 잘 모르겠으면 먼저 `12-DB-테이블-보기.cmd`로 테이블 이름만 확인한 뒤 11번을 쓰는 편이 쉽습니다.

11. 12-DB-테이블-보기.cmd
   - 현재 DB 테이블 목록만 빠르게 보여줍니다.
   - 이 명령은 "보기 전용"처럼 쓰면 됩니다.
   - 사용자가 입력하거나 선택할 것은 없습니다.
   - 실행하면 테이블 이름 목록이 한 번 출력되고, 창이 그대로 유지됩니다.
   - 테이블 이름만 확인하고 닫고 싶을 때 가장 쉬운 명령입니다.

[11번/12번 쉬운 설명]
- 11번은 "직접 입력해서 자세히 보는 창"입니다.
  - 예: app_users 안에 실제 데이터가 뭐가 들어있는지 보고 싶을 때
- 12번은 "테이블 이름만 빠르게 보는 창"입니다.
  - 예: 어떤 테이블들이 있는지만 확인하고 싶을 때
- 무엇을 선택해야 하나요?
  - 12번은 아무것도 선택할 필요 없습니다. 그냥 실행해서 목록만 보면 됩니다.
  - 11번도 따로 선택은 없습니다. 창이 열리면 글자를 직접 입력하면 됩니다.
- 처음에는 보통 이렇게 쓰면 됩니다.
  1. 12-DB-테이블-보기.cmd 실행
  2. 보고 싶은 테이블 이름 확인
  3. 11-DB-콘솔-열기.cmd 실행
  4. 예: `select * from app_users;` 입력 후 Enter
  5. 끝나면 `\q` 입력 후 Enter

[자주 쓰는 순서]
1. 서버 실행
   - 03-서버-열기.cmd

2. 상태 확인
   - 05-서버-상태-확인.cmd

3. 최초 관리자 만들기
   - 06-오너-생성.cmd

4. 일반 직원 만들기
   - 07-일반직원-생성.cmd

5. 비밀번호 바꾸기
   - 08-비밀번호-재설정.cmd

6. 계정 삭제
   - 09-사용자-삭제.cmd

7. DB 콘솔 열기
   - 11-DB-콘솔-열기.cmd

8. DB 테이블 빠르게 보기
   - 12-DB-테이블-보기.cmd

[운영 팁]
- 내부 직원이 주로 쓸 경우, 같은 주소로 접속을 통일하는 것이 좋습니다.
- 로그인 문제를 줄이려면 내부에서는 내부 주소만, 외부에서는 외부 주소만 사용하도록 맞추는 편이 좋습니다.
- username 은 영문으로 두고, 표시 이름(display name)에 한글을 쓰는 방식이 가장 안정적입니다.
- GUI 도구(DBeaver, pgAdmin)를 쓰고 싶으면 .env.production.local 의 KPI_DATABASE_URL 정보를 그대로 사용하면 됩니다.
